# GoalBridge – Goal-Based Investment Planner

GoalBridge is an educational financial-planning web application that helps users translate a present-day financial goal into an estimated future goal cost and monthly contribution requirement. It supports comparing assumptions for the same goal, explaining the funding mix, and printing selected plans.

The application is intended for educational scenario planning, not investment advice. Calculations run in the browser without registration, an account, or financial-service connections.

## Core features

Enter six inputs: **Goal Name**, **Goal Amount Today**, **Current Savings**, **Years to Goal**, **Expected Annual Inflation**, and **Expected Annual Investment Return**.

The result cards show:

- Inflation-adjusted **Future Goal Cost**.
- **Future Value of Existing Savings** at the assumed return.
- **Funding Gap** after accounting for those savings.
- **Required Monthly Contribution** at the end of each month.
- **Total Monthly Contributions** across the goal period.
- **Projected Investment Growth** generated by those monthly contributions.

Currency uses Indian Rupee formatting with Indian digit grouping and two decimal places. Three independent funding bars show savings, contributions, and projected growth relative to the future goal cost. Bars are capped at full width when savings exceed the goal; the actual savings amount remains visible.

**Your Plan** explains today's cost, the estimated inflation increase, existing savings, the remaining gap, and the contribution/growth mix. It handles zero return, no savings, and already-funded goals without implying guaranteed outcomes.

### Validation and accessibility

Goal names are trimmed, so whitespace-only names are invalid. Goal amount must be positive; current savings may be zero. Years must be a positive whole number. Both annual rates accept zero and are limited to 100%.

The form also enforces its existing ranges and increments: 1–100 years; currency amounts up to ₹1 trillion in ₹0.01 increments; and rate increments of 0.1 percentage points. Goal amount has a ₹0.01 minimum. Missing, invalid, negative, or out-of-range inputs receive validation feedback, with focus moved to the invalid field.

Labelled inputs, native buttons, visible keyboard focus, semantic headings/tables, chart descriptions, and live status/error messages support keyboard and assistive-technology use. Responsive layouts adapt the form, result cards, graphs, and comparison data for smaller screens, including approximately 375px width.

## Comparing scenarios

The comparison holds **three scenarios at most**: one Base Plan and two alternatives, all for the same goal.

1. The first successful calculation establishes the **Base Plan**.
2. Click **+ Create Alternative Scenario** to enter an explicit creation mode. The existing form is pre-filled from the Base Plan, with Goal Name temporarily read-only.
3. Change assumptions and click **Calculate Alternative Scenario**. Only a valid calculation saves the alternative. Cancel exits creation mode and restores the latest calculated inputs.
4. Repeat for a second alternative. The Create button then becomes disabled and explains the limit.

Ordinary recalculations update the main result cards and educational summary without overwriting saved scenarios. Each saved scenario has a funding card. Once an alternative exists, **Compare Your Scenarios** shows monthly-contribution and funding-gap bar charts, a side-by-side assumptions/results table, and a deterministic educational interpretation. Charts show actual INR amounts and use a shared scale within each chart. Mobile tables become stacked metric groups.

Each alternative has a Remove control; the Base Plan does not. Removing an alternative preserves the other, and the next creation reuses the vacant numbered slot. **Reset Comparisons** clears saved comparisons while retaining the current calculated results; the next successful calculation establishes a new Base Plan. The main **Reset** separately restores HTML input defaults, clears results and comparisons, and hides printing until another valid calculation.

## Selective Print / Save

After calculation, **Print / Save Plan** opens a native dialog listing only available saved scenarios. Options start selected, with **Select All Available Scenarios**, **Print Selected**, and **Cancel** controls. At least one selection is required. Escape also closes the dialog, and focus returns to the print button.

- **One selected scenario:** its assumptions, results, funding visual, educational summary, and disclaimer; no comparison section.
- **Two or three selected scenarios:** each selected summary plus graphs, table columns, and interpretation restricted to that selection. Either alternative can be printed without the Base Plan.

If Base Plan is excluded, the first selected alternative becomes the comparison reference. After Reset Comparisons, a remaining calculated result is available as **Current Plan**. While saved scenarios exist, the selector prints their saved snapshots rather than unsaved form edits or an ordinary recalculation that was not saved as an alternative.

Printing uses `window.print()` and the browser's **Print → Save as PDF** option. There is no external PDF library. Print CSS hides interactive controls and keeps cards, charts, and rows together where practical. Pagination can vary with browser and printer settings. Use the application button to select scenarios; the browser's direct print shortcut does not open this selector.

## Financial calculation methodology

[finance.js](finance.js) is the single source of truth. Its exported `calculatePlan(inputs)` accepts validated numeric inputs and returns numeric results without DOM access or currency formatting. Both the application and unit tests use this function.

Let `G` be today's goal amount, `S` current savings, `Y` years, and `I` and `R` annual inflation and return **as decimals**. UI inputs are percentages: the engine converts 6 to 0.06, for example. Let `N = Y × 12`.

```text
FutureGoal    = G × (1 + I)^Y
FutureSavings = S × (1 + R)^Y
FundingGap    = max(0, FutureGoal − FutureSavings)
MonthlyRate   = (1 + R)^(1/12) − 1

If FundingGap = 0:
    PMT = 0
Otherwise, if MonthlyRate = 0:
    PMT = FundingGap / N
Otherwise:
    PMT = FundingGap × MonthlyRate / ((1 + MonthlyRate)^N − 1)

TotalContributions = PMT × N
ProjectedGrowth    = max(0, FundingGap − TotalContributions)
```

The monthly rate is the effective compounded rate, **not annual return divided by 12**. The ordinary-annuity formula assumes end-of-month contributions. Zero return is handled directly without an artificial replacement rate or division by zero. Values are rounded only for display. The nonnegative growth guard removes meaningless negative floating-point residue.

### Assumptions and limitations

Inflation and assumed investment return remain constant throughout the horizon. Existing savings grow at the entered return; monthly contributions remain constant and occur at month-end. Taxes, fees, transaction costs, product-specific charges, contribution increases, and market volatility are not modelled. Projected growth refers to growth on monthly contributions; growth of existing savings is already included in their future value. Actual costs, inflation, and returns can differ. This is an illustrative model, not a prediction or product recommendation.

## Running locally on Windows

Install Node.js with npm and use a modern browser supporting ES modules and native dialogs. From PowerShell:

```powershell
Set-Location "D:\Desktop Data 4 Aug 2026\FPA\AI\GoalBridge_Invest_Plan"
npm.cmd install
npx.cmd serve .
```

Substitute your own checkout directory if different. Open the local URL printed by the server. Stop the server with Ctrl+C. Serve the project root so `index.html`, `script.js`, and `finance.js` resolve together; do not simply double-click `index.html`, because browser ES-module loading requires an HTTP(S) origin.

`npm.cmd install` installs development/testing dependencies; the browser application itself needs no npm dependencies to execute. `serve` is a local-server utility invoked through npx, not an application dependency; npx may request a download on first use. No environment variables or API keys are needed.

## Privacy and security

No registration, personal account, financial-product recommendations, or external financial API is required. Calculation and scenario/print-selection data remain in page memory; no localStorage, sessionStorage, cookies, database, analytics, or tracking code is used by the application. Reloading the page clears its stored scenario snapshots. No API keys or secrets are needed. User-entered names are inserted as text rather than executable HTML. A PDF saved through the browser is a user-created file, not application-side persistence. Hosting services may separately maintain normal request logs; this README does not claim a formal security audit.
